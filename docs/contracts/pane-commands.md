# Pane and window operations

These are proposed native contracts from the pinned Python and tmux 3.3/3.8
sources. They are not implemented or runtime-qualified. Remaining output,
encoding and capability questions are implementation gates, not permission to
omit required operations.

External acquisition and mutation use explicit `IO`, the pinned generation,
no-start transport and bounded ownership. Validate mutually exclusive modes,
checked values and capabilities before dispatch. Preserve asynchronous
cancellation. Completion means command processing, including documented no-ops;
it does not prove target survival, application consumption or later UI action.
Retain primary receipts if a later observation fails. Errors can follow partial
effects; uncertain outcomes are never automatically replayed.

Physical references identify entities. Explicit context identifies a session,
window link or native current occupant where required. A bare pane/window ID
does not select a unique session. Contextual preflight is not a reservation.

## Required modes

| Contract / source operation | Input and target | Result and completion |
| --- | --- | --- |
| B1 — `session.last-window/next-window/previous-window` | Exact `SessionRef` and one navigation action. | Return completion; optional subsequent active `WindowLink` is a separate observation. Missing navigation candidate is an error. Do not return the old captured active window as the command's selected result. |
| B2 — `session.rename-session`, `window.rename-window`, `pane.set-title` | Exact entity; literal text or explicitly expanded tmux format, with an explicit context for expansion. | Return completion, optionally followed by a fresh observation. Both releases expand these operands. Literal lowering therefore needs qualification. Session duplicate/invalid name errors remain concrete; window rename also disables automatic renaming. A successful title change is not pane selection. |
| B3 — `pane.select`, `window.last-pane` | Distinct `SelectExact`, `SelectDirection`, `SelectLast`, `ToggleMark`, `ClearMark`, or `SetInputEnabled` intents; explicit anchor/context. `keepZoom` belongs only where applicable. | Return completion, with separate later selection/mark/input observation. `-m` toggles rather than idempotently sets; direction may succeed without changing selection; last-pane can error. Input enable/disable and marking are not ordinary selection. Floating marking has additional selection behavior in 3.8. |
| B4 — `pane.split`, `pane.new-pane` | `Split` versus `CreateFloating`; exact anchor and execution context; checked direction, size/percentage, full-window, detach/selection, zoom, launch, cwd and environment. Both creation modes retain capability-gated style, active/inactive border styles, message and keep options. Floating creation additionally has optional width/height and signed x/y placement; qualify cell/percentage bounds and border interpretation. | Create-only returns an actual historical pane-ID receipt plus observed context when obtained. Remove generic reuse/replace modes: these operations do not implement them. A receipt does not prove successful exec or continued life. Missing receipt after dispatch is uncertainty, not safe retry. `new-pane` is unavailable on 3.3; splitting an already floating pane can itself create a floating pane on 3.8. |
| B5 — `pane.resize` including width/height wrappers | Exact pane target; `ResizeAbsolute` with at least one checked dimension, directional adjustment, `ToggleZoom`, `TrimBelow`, or event-backed mouse resize. | Return completion; later dimensions are observed actual values, not guaranteed requested sizes. Layout constraints can clamp changes. `trim_below` is its own history/screen operation and overrides ordinary sizing in tmux. Mouse behavior requires a real event context; a standalone argv request must not claim a resize happened. |
| B6 — `window.resize` | Physical window plus needed session context; absolute size, directional adjustment, fit-largest-client, or fit-smallest-client. | Return completion and optional observed dimensions. Resizing sets `window-size` to manual. No generic expand/shrink flag bundle; validate all sizes before dispatch and preserve partial-effect errors. |
| B7 — `window.select-layout/next-layout/previous-layout` | Exact window target, with an explicit pane anchor for spread; one named layout, versioned serialized layout, reapply-last, next, previous, or spread-around-explicit-pane action. | Return completion; a separate observation supplies the resulting layout. Invalid layout can still unzoom the window before failure. Serialized layouts need producer/version metadata; do not promise portable strings across layout-format revisions. `spread` requires a pane anchor, not merely a physical window ID. |
| B8 — `window.rotate` | Physical window, one direction, and zoom policy. | Return completion; retain pane identities while changing their positions and active-pane state. Do not label this as changing only geometry or preserving the active pane. |
| B9 — `pane.respawn`, `window.respawn` | Exact physical entity plus execution context; `OnlyIfStopped` or explicit `ReplaceRunning`; reuse-stored command/cwd or checked replacements and environment. | Return restart-processing evidence, not a new pane identity or successful exec result. Pane respawn preserves its pane ID but replaces process/screen state. Window respawn destroys all but the first pane before respawning that survivor. Failure can follow destruction/reset; there is no rollback or all-descendants-exited guarantee. |
| B10 — `pane.move`, `pane.join` | Explicit source pane/context and destination pane, or explicitly current active pane of a window; orientation, before/after, size/full-window, and selection policy. | Return completion, preserving the moved pane ID. Moving the last pane can destroy the source physical window and its links; both windows' layout/options/selection may change. Same-pane tiled operation errors; 3.8's same-pane floating case can tile it. Keep floating placement extensions separate from the shared move/join subset. |
| B11 — `pane.break-pane` | Explicit source pane **and source-link context**, destination session/placement, detach/selection, optional checked name. | Return `BreakAccepted` with an optional verified destination receipt and an independently established created/transferred classification. Breaking a sole pane transfers an existing window link; 3.3 returns before `-P`, while 3.8 prints a receipt. Do not infer creation from a receipt or classify from a prior pane count. A later location read is an observation, not an execution-time receipt. |
| B12 — `pane.swap` | Two exact panes, or one pane plus previous/next-by-pane-order; explicit detach/zoom policy. No contradictory target/direction bundle. | Return completion and optional later topology. Pane IDs survive and may change windows/options. Relative swap wraps through pane order, not spatial adjacency; 3.8 skips tiled-ineligible panes and rejects a floating relative anchor. `-d` can change which pane identity occupies the selected location. |
| C1 — `pane.capture-pane` (all three declarations) | Exact pane target; explicit screen/history range and source: ordinary, native alternate, mode screen, pending input parser data, or hyperlink listing; checked rendering flags. Separate output destination: returned bytes or named server buffer. | Returned bytes are **tmux command rendering**, not original process output or a portable terminal replay. Preserve trailing blank rows. Buffer mode returns completion, not byte data. Missing alternate screen errors unless that specific quiet policy is selected; quiet does not suppress arbitrary errors. Unsupported flags fail before dispatch. Exact pane-only bytes remain gated on output provenance described below. |
| C2 — `pane.send-keys`, `pane.enter`, `pane.send-prefix` | Separate literal text, named keys, checked hex bytes, copy-mode command/arguments, reset, mode-repeat prefix, and explicit client-key routing. Checked repeat; explicit Enter step and optional leading space. Prefix sending selects primary versus secondary prefix and needs an explicit session context. Enter alone sends one Enter event. | Return input-request processing evidence. It is not proof the application received or executed input. Invalid hex/key names must not silently fall back or disappear. Reset/copy-mode/client-key routing have distinct capability and target rules. Sending text then Enter is a multi-step effect; preserve partial/unknown outcomes. Leading space only requests a shell convention, not history suppression. |
| C3 — `pane.paste-buffer` | Exact pane; named buffer or current-top intent; keep/delete-after-request; newline policy (CR, LF, explicit separator); conditional bracket mode; explicit byte transformation policy. | Return processing evidence. Missing named buffer errors; empty top-buffer selection can succeed with no input. Input-disabled pane can receive nothing while `-d` still deletes the buffer. Brackets are inserted only when the pane mode enables them. 3.3 writes bytes directly; 3.8 escapes unsafe bytes unless `-S`. Never claim raw preservation from a version-neutral default. |
| C4 — `pane.pipe` | Exact pane/context; `Close`, `Replace shellPayload direction`, or native toggle; output, input, or both directions. Formats/time expansion are explicit. | Return setup/close processing evidence, not pipe-child exit or durable log completion. The old pipe closes before replacement validation/fork succeeds. `-o` closes an existing pipe; it does not preserve it. The pipe and shell are daemon-side state and can outlive the library client. Do not implement a scoped stream by silently taking over this sole per-pane pipe. |
| C5 — `pane.copy-mode`, `pane.clock-mode` | Copy enter, page-up/down, exit-on-bottom, cancel, optional exact source pane; or clock entry. Mouse drag requires event-backed mode. | Return processing evidence, not a UI interaction result. Copy cancel resets modes. Unsupported page-down is an error, not silently ignored. Mode entry may be an accepted no-op; ordinary command execution does not provide a mouse event. |
| C6 — `pane.choose-buffer/choose-client/choose-tree/customize-mode/find-window` | Explicit display pane/context. Tree collapse/sort/reverse/zoom are checked; format/filter and find pattern/dialect are explicit native languages. | Return mode-request completion only. No selected entity, buffer, or completed customization is returned. Empty buffer/client candidates can succeed without opening a chooser. `find-window` enters tree mode; it is not a collection query. Its regex lowering differs between 3.3 and 3.8, so common-subset semantics need qualification. |
| C7 — `pane.clear-history`, `pane.clear`, `pane.reset` | Exact pane target; three separate actions: clear tmux history with gated hyperlink reset; send the text `reset` then Enter; reset tmux terminal state followed by clear-history. | Return processing or ordered step outcomes. `clear` requires an application that interprets that input as desired; it is not a terminal reset primitive. `reset` is a nontransactional sequence. Clear-history also exits modes; it does not prove all display content, shell history, or hyperlink state was cleared. |

## Protocol and migration qualifications

1. **Keep output provenance separate from EOF framing.** `capture-pane` and listing commands have after-hooks. Hook items inherit the requesting client and can print into the same stdout. EOF delimits the invocation, not pane-only bytes. Arbitrary capture content prevents a delimiter alone from proving provenance. Qualify an isolated output mechanism before offering that stronger result; checking hooks first races with changes. Also, `capture-pane -p` removes one terminal LF and appends one: pending data without LF is indistinguishable from that data with LF. Raw rendering must preserve this limitation. [Capture handler](https://github.com/tmux/tmux/blob/87fe00e8b44901240fc22d7120c1b31e4331f6f5/cmd-capture-pane.c), [hook client inheritance](https://github.com/tmux/tmux/blob/87fe00e8b44901240fc22d7120c1b31e4331f6f5/cmd-queue.c#L323)

2. **Do not advertise unqualified literal or direct-exec guarantees.** Process argv prevents a shell at the outer boundary, but tmux separates arguments ending in an unescaped semicolon. Creation cwd, renames, titles, ACL names, and pipe commands have further expansion rules. In both releases, a one-element spawn argv uses `shell -c`; only multiple elements use `execvp`. An executable with zero arguments needs a qualified lowering. A missing cwd can fall back, and fork success precedes exec failure. Empty pane creation is distinct from an empty command default: 3.3 can create an empty pane with a single empty command; 3.8 also has `-E`. These are source-supported lowering candidates, not tested equivalence. [Argument parser](https://github.com/tmux/tmux/blob/87fe00e8b44901240fc22d7120c1b31e4331f6f5/cmd-parse.y#L1042), [spawn](https://github.com/tmux/tmux/blob/87fe00e8b44901240fc22d7120c1b31e4331f6f5/spawn.c#L228)

3. **Fix creation and topology classifications.** Remove reuse/replace from split/floating creation. Break-pane needs accepted/receipt distinctions and explicit source-link context; a bare pane ID may select the wrong link to unlink. Respawn preserves an entity ID across process replacement, so cached process/output continuity must be invalidated independently. Moving the last pane and window respawn have wider effects than their singular API names suggest. [Break on 3.3](https://github.com/tmux/tmux/blob/87fe00e8b44901240fc22d7120c1b31e4331f6f5/cmd-break-pane.c#L79), [break on 3.8](https://github.com/tmux/tmux/blob/7f2a35ad3321f9ba57a1062ca73b1f3ff26aca53/cmd-break-pane.c#L130), [respawn destruction](https://github.com/tmux/tmux/blob/87fe00e8b44901240fc22d7120c1b31e4331f6f5/spawn.c#L88)

4. **Do not inherit hidden failure or transformation.** Python capture/send/enter/reset omit reliable failure checks; the common process wrapper strips all trailing empty output lines and decodes invalid UTF-8 with replacement escapes. Preserve native bytes and concrete failures instead. `send-keys -F` is not generic text-format expansion: the ordinary string injection path uses the supplied string, while supported copy-mode commands interpret `-F`. `-K` routes through client key handling, not merely a key-name parser. [Python capture and send](https://github.com/tmux-python/libtmux/blob/957d4bdcfbf978607fb58a6c0f167d74ec3137ec/src/libtmux/pane.py#L492), [Python transport](https://github.com/tmux-python/libtmux/blob/957d4bdcfbf978607fb58a6c0f167d74ec3137ec/src/libtmux/common.py#L283), [key handler](https://github.com/tmux/tmux/blob/7f2a35ad3321f9ba57a1062ca73b1f3ff26aca53/cmd-send-keys.c)

5. **Preserve release-specific meaning.** Capture `-H` returns hyperlink URIs rather than decorating ordinary captured text; mode-screen capture can fall back to the base screen. Paste transformation, find-window regex construction, command lookup, floating panes, layout formats, and client-target fallback differ at the inspected endpoints. Do not interpolate a minimum release from Python guards or from endpoint comparison alone. [Modern capture](https://github.com/tmux/tmux/blob/7f2a35ad3321f9ba57a1062ca73b1f3ff26aca53/cmd-capture-pane.c), [paste transformation](https://github.com/tmux/tmux/blob/7f2a35ad3321f9ba57a1062ca73b1f3ff26aca53/cmd-paste-buffer.c), [find-window regex lowering](https://github.com/tmux/tmux/blob/7f2a35ad3321f9ba57a1062ca73b1f3ff26aca53/cmd-find-window.c)

6. **Waiting is not a cancellable lease.** The existing waiting-admission contract remains necessary for raw commands and any future split `-W` mode. 3.8 adds per-client pending-wait cleanup absent from the inspected 3.3 handler; this does not release an acquired server lock. 3.8 also permits explicit waiter wakeup, so a completed lock wait is not proof of exclusive lock ownership against other actors. Reaping a local waiting process cannot erase uncertain server-side work on 3.3. Keep signaling/inspection capacity independent and retain unresolved debt until qualified cleanup or server retirement. [3.3 wait state](https://github.com/tmux/tmux/blob/87fe00e8b44901240fc22d7120c1b31e4331f6f5/cmd-wait-for.c), [3.8 wait/wake/cleanup](https://github.com/tmux/tmux/blob/7f2a35ad3321f9ba57a1062ca73b1f3ff26aca53/cmd-wait-for.c)

7. **Treat aliases as migration evidence.** `Window.split_window`, `Pane.split_window`, `Pane.select_pane`, and `Pane.resize_pane` raise `DeprecatedError` at the pin. They are not runtime forwarding aliases. `set_width`/`set_height` do forward, and window split/floating wrappers choose an active pane first. A native exact-anchor API deliberately removes that hidden acquisition/selection step; document the replacement rather than claiming identical execution. [Python aliases](https://github.com/tmux-python/libtmux/blob/957d4bdcfbf978607fb58a6c0f167d74ec3137ec/src/libtmux/pane.py#L2762)

The next specification revision can use this matrix while retaining `SPECIFIED_PENDING_PROTOCOL_QUALIFICATION` and `UNVERIFIED`. Highest-value qualification cases are arbitrary output plus hooks; trailing-LF/pending capture; one-element exec and missing cwd; sole-pane break on both releases; respawn/fork failure; pipe replacement failure; disabled-input paste with deletion; linked-window contexts; and cancellation with pending server work. Exact intermediate-release capability boundaries remain open.


## Operation-specific selection

The grouped rows describe related commands, not a shared set of flags for every
function. `lastPane` selects the last pane or changes that pane's input-enabled
state; it has no mark/direction modes. `nextLayout` and `previousLayout` select
only their named navigation action. `enter`, `sendPrefix`, `clockMode`,
`clearHistory`, `clear` and `reset` retain their individual inputs and outcomes
in the inventory. Floating placement distinguishes default geometry from checked
width/height and signed x/y offsets; requested geometry is not a guarantee about
the eventual layout after border rules and constraints.
